# CoreTend 0.8.0 (prerelease) — Functional Completion

Closes every automatable item in the 21-step functional-completion plan
(`Documentation/FUNCTIONAL_COMPLETION_EXECUTION_PLAN.md`). Feature and
hardening pass — no rename, still CoreTend, still local-only.

## Changes since 0.7.1

- **Cleanup finalized** at 10 built-in rules (user caches, logs, crash
  reports, Xcode DerivedData, incomplete downloads, Xcode device support,
  iOS device backups, old installers, old archives, Xcode Archives) — all
  user-domain, all Trash-based. Four candidates (iOS Simulator data,
  Trash-emptying, Mail attachments, broken LaunchAgents) were deliberately
  **not** shipped as blind extension/age rules; each needs a dedicated
  safety engine and is documented with its rationale in
  `Documentation/REQUIREMENTS_DECISION_HISTORY.md`.
- **Protection's optional FSEvents watch** had its full scenario matrix
  closed: single event, burst coalescing, multiple files, temp files,
  deleted-before-scan, still-growing/unstable files, unmounted volumes,
  ClamAV-absent, dedup, cancellation, disable, restart persistence,
  rename independence, and rate limiting. Off by default, never
  auto-quarantines.
- **My Clutter** (Large & Old, Duplicates, Similar Images) gained name
  search, real volume awareness (a stable per-volume identifier, never
  the display name two different drives can share), and UI-exposed
  exclusions — all routed through the same exclusions list Settings
  already manages, not a second system.
- **Space Lens** and **Cloud Cleanup** testability work: navigation logic,
  provider detection, and sync-state classification are now covered by
  fixture-based tests instead of only manual verification.
- **macOS compatibility audit**: every API used sits at or below the
  macOS 14.0 floor; no `@available` guards needed.
- **9 synthetic stress fixtures** covering large findings sets, worst-case
  duplicate buckets, wide/deep directory trees, SQLite history at scale,
  and FSEvents bursts — no bugs found.
- **Code-level accessibility audit** across every SwiftUI view: labeled
  controls, non-color warning signals, a treemap summary for VoiceOver,
  decorative icons hidden.
- **8-step first-run wizard**, re-launchable from Settings, with tested
  pure logic (security profile safety invariant, launch-location
  detection, system self-check, ClamAV version parsing).
- **Fixed the last Sendable concurrency warning** — Debug and Release
  builds now show zero project warnings.
- Documentation fully synced to actual shipped scope: 7 new per-module
  docs, corrected roadmap/feature-matrix claims, a documented decision
  history for every deferred safety-sensitive function.

215 → 250 tests, 0 failures, 0 build warnings.

**Pre-1.0 releases are currently distributed without a Developer ID
signature and without Apple notarization.** Not a public GitHub release
yet — see `Documentation/HUMAN_BLOCKERS.md`.

## Known limitations

- Unsigned, not notarized: Gatekeeper will block first launch (see
  `Documentation/INSTALL_UNSIGNED.md`).
- Built and tested on a single physical Mac (macOS 26.5.1, arm64) — no
  multi-OS or multi-hardware verification performed.
- Interactive VoiceOver verification and a full FR/EN × light/dark ×
  every-module screenshot campaign are not done — a real display is
  available in the environment this was built in and one verification
  capture succeeded, but the full campaign is separate remaining work
  (`Documentation/VISUAL_QA.md`, `KNOWN_LIMITATIONS.md`).
- No public GitHub release exists yet; this manifest has no downloadURL.
