# CoreTend 0.8.1 (prerelease) — CoreTend Rebrand & Workspace Migration

**The product formerly called MacCare Local is now CoreTend.** This is a rename
and a reorganisation. Nothing about what the app does changed.

## If you used the previous version

Your data comes with you, and your old copy stays where it is.

Renaming a macOS app orphans two independent classes of local data: the
Application Support directory, which the app names, and the `UserDefaults`
domain, which macOS names from the bundle identifier. Both migrate on first
launch.

The migration **copies** — it never moves, renames, or deletes anything in
`~/Library/Application Support/MacCareLocal/`. Your activity history,
exclusions, settings, quarantine, and onboarding state appear under the new
identity, and the previous version's folder remains intact beside it. That is
what makes the rename reversible: if you go back to an older build, it finds
its data exactly where it left it.

Consequences worth knowing:

- **Two copies exist afterwards.** Deliberate. The uninstaller leaves the old
  one alone unless you pass `--include-legacy`, because after a migration it may
  be your only intact copy.
- **Existing new-identity data always wins.** If you had already run a CoreTend
  build, the migration will not overwrite it.
- **Interruptions are safe.** Each item copies independently through a temporary
  name, so a crash mid-migration leaves nothing half-written, and rerunning
  finishes the job.
- **Failures are visible.** If something cannot be copied — permissions, a full
  disk, an unreadable file — Settings says so, naming the item and the reason.
  Nothing is silently skipped.

## Renamed

Sources, SwiftPM package and targets, executable, app bundle, resources, both
localisations, scripts, CI workflows, documentation, website, and legal
metadata. The bundle identifier is now `com.ahmetbsbnr.coretend`.

The old name survives in four places on purpose, because erasing it would
falsify a record or break the migration: rename history, historical release
artifacts (including these notes' predecessors), user-data compatibility, and
the Apache-2.0 licence text. `Scripts/check-legacy-brand-references.sh` fails on
any other occurrence, and an allowlist entry only counts if it states its
reason.

## Living System

The visual identity is named and enforced rather than described. Canonical brand
values are used on dark surfaces; light surfaces use darkened siblings of the
same hues, because several canonical values measure under 4.5:1 against a
near-white background. Contrast tests hold both directions, and one of them
fails deliberately if the canonical accent ever *would* pass on light — that is
the assumption the whole split rests on.

A complete asset set is generated from one set of numbers shared with the app's
own Core Bloom geometry: app icon 16–1024 and `.icns`, menu-bar templates,
favicons, horizontal and compact lockups in light, dark and single ink, an
onboarding hero, an Open Graph card, a DMG background at 1x and 2x, and SVG plus
PDF vector sources.

## Website

Rebuilt on the new identity: bilingual, static, responsive, keyboard-navigable,
light and dark. It makes **zero external requests** — no webfont, no CDN, no
analytics, no cookies, and as of this release no JavaScript at all. The download
page's script was an inert renderer whose only behaviour was printing one static
sentence; it is HTML now.

`Scripts/check-website.sh` enforces that, plus locale parity, internal link
integrity, an accessibility floor, and an editorial bar strict enough to be
useful — it reads sentences rather than files, so the copy can honestly deny a
claim it must not make.

## Still not published, and why

- No trademark or prior-usage search has been run for the name CoreTend. None is
  claimed. `Documentation/BRAND_SEARCH_EVIDENCE.md` says so in those words.
- `legalReviewStatus` is `pending`, and `publicReleaseAllowed` is false.
- Legal identity and a security contact are still undefined.
- Builds remain unsigned and un-notarized.

`Scripts/check-brand-clearance.sh --publication` fails until the first three
change. `--engineering` passes, which is what authorised this release locally.
