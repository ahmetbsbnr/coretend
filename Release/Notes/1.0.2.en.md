# CoreTend 1.0.2

A safety patch. Two guards inside CoreTend did not guard, and one of them had
never guarded since the first public commit. That is why this release exists.
It also carries the four correctness fixes merged since 1.0.1 — each one a case
of the app knowing something and not telling you.

## Protected system paths could be walked past

CoreTend refuses to touch a set of protected system locations — `/System`,
`/bin`, `/usr/lib`, Gatekeeper's database and others — no matter what a scan
proposes or a rule allows. Two independent flaws let a path reach past that
refusal.

**Spelling.** The check compared paths case-sensitively. macOS volumes are
case-**in**sensitive by default, so `/system/Library/CoreServices` is the same
directory as `/System/Library/CoreServices` — and only the second was
recognised. `/Bin/ls` and `/usr/BIN/whoami` behaved the same way.

**Symlinks.** The check only ever looked at the path as written, never at what
it resolves to. macOS ships `/etc`, `/var` and `/tmp` as links into
`/private`, and the protected list is written in `/private` form — so
`/var/db/SystemPolicy`, Gatekeeper's own database, and `/etc/passwd` passed
the check cleanly.

### How much this mattered

Less than it sounds, and the honest figure is worth more than an alarming one.

System Integrity Protection is on by default on every supported Mac, and the
locations these flaws reach are root-owned and SIP-restricted: macOS refuses
the operation regardless of what CoreTend decides. CoreTend only ever moves
items to the Trash — it never deletes — so anything it did touch would remain
recoverable. And reaching the flaw at all required an allowlist already
containing an ancestor of a system root, which means a scan pointed at `/` or
similar.

A guard that did not guard, standing behind two guards that do. It is fixed
with the urgency a broken guard deserves and described with the accuracy the
outcome deserves.

There is no way to tell whether anyone ever encountered it. CoreTend reports
scan locations nowhere, by design, because it has no telemetry — so that
question has no answer and will not get one.

## The Safety Log could lose entries without saying so

Every move, refusal and failure is written to an append-only log that is the
only record a file was ever touched. When a write to that log failed, nothing
anywhere learned of it: the failure was discarded, and the record was simply
short.

The log's writer still cannot interrupt the work it records — an audit trail
that can abort an operation is a worse problem than a missing line. What
changes is that a failed write is now counted, and the Safety Log states the
count beside its own totals rather than quietly omitting it.

## Also in this release

**Cleanup screens now say what they skipped.** CoreTend re-checks every item at
the moment it moves it, and refuses anything that changed since you approved
it. Those refusals were counted internally and never shown: ten files selected,
three refused, and the screen said "Moved 7 items to Trash". A refusal is the
product, not a footnote on it. In Explore, a single refused item refreshed
nothing and showed no alert, so the click simply looked ignored.

**Dates follow the language you chose in the app.** The language picker changed
the interface text and nothing else, so on an English Mac set to French every
date still read English. Nine places across six screens.

**Integrity no longer claims ignorance about files it knows.** The downloads
list read one macOS quarantine key and, finding it empty, said "no provenance
recorded" — while macOS had recorded which app brought the file in and on what
day under a different key. Measured on a real Mac: 280 quarantined files, none
with the key CoreTend read, all 280 with provenance under another.

**Cleanup rows show the evidence the scan already had.** Size is the weakest
signal for deciding whether a file should go. Rows now show risk level and how
long ago the file was touched — which also makes visible what decides whether a
row is ticked for you.

## Upgrading

Replace 1.0.1 with this build. No data migration, no settings change, nothing
to re-grant.
