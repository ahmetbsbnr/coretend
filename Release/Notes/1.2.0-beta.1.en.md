# CoreTend 1.2.0-beta.1

The first beta of **Deep Scan**, a substantially deeper macOS storage-analysis
and cleanup system. This is a beta: the analysis is complete and reviewed, but
the cleanup step is deliberately narrow and everything requires a deliberate
selection.

## Deep Scan (beta)

A new sidebar module. It performs a read-only, evidence-based look at where
storage goes:

- **Full-disk analysis** — a bounded, cancellable walker builds a disk graph
  with truthful sizes (logical vs allocated), per-node scan completeness, and
  real volume classification. It stops at mount boundaries, records — never
  guesses — permission-denied folders, and never treats a partial scan as a
  full one.
- **AI / LLM storage analysis** — recognises LM Studio, Ollama, Hugging Face,
  MLX, llama.cpp, Claude Code, Codex, Cursor and classifies each store by data
  type. Model weights are review-only. Saved memory, conversation history,
  per-project state, sign-in credentials and configuration are **protected**
  and shown (with size and rebuild cost) but never selectable. Anything a
  profile does not positively identify is protected until it is.
- **Git project hygiene** — per repository: remotes, branch, HEAD, dirty
  state, stashes, local-only commits, worktrees, remote-verification state,
  classified GREEN / YELLOW / RED with a plain-language explanation. A
  repository is **never** automatically selected. Stale worktree
  registrations and duplicate clones are surfaced separately.
- **App leftover detection** — orphaned application data identified by exact
  bundle-ID match (self and embedded helpers), not name guessing. Weak,
  name-only matches are high-risk or protected.
- **Developer storage analysis** — build output (`.next`, `dist`, `build`,
  `target`, `.build`, `DerivedData`, coverage), each with an explicit
  reconstruction cost. Build directories inside a dependency store
  (`node_modules`, Pods, site-packages) are excluded — they belong to an
  installed package.
- **System / settings detection** — orphaned launch agents and similar
  remnants, detection-only, review-only. No "optimise macOS" claims.
- **Incremental FSEvents index** — after the initial scan a live watcher keeps
  a persisted SQLite index roughly in sync via coalesced, scoped rescans;
  dropped events mark the affected scope stale and trigger a full rescan; the
  index is never presented as current while stale.
- **Safe evidence model** — every finding carries a machine-checkable evidence
  trail, a risk level, a confidence level, a reconstruction cost, and two
  plain-language lines ("why" and "what happens if removed"). Scoring is
  deterministic — no AI, no network, no telemetry.
- **Manual cleanup plan** — before anything moves, a plan shows the selected
  items, totals, risk and rebuild summaries, what is protected, and what
  changed since the scan.
- **SafetyCenter revalidation → Trash → Journal → Restore** — the only path to
  a change re-checks path identity, symlink state, active writes, owning-app
  state and enclosing-repo state, then hands survivors to the existing
  SafetyCenter, which moves them to the macOS Trash and records a journal
  entry. Restore Center reinstates them.

Deep Scan is fully localized in English and French.

## Beta boundaries — read this

- **Deep Scan is beta.** Report anything that looks wrong.
- **Automatic preselection is disabled.** Nothing is ever pre-ticked; every
  cleanup item needs a deliberate selection.
- **Git repositories are never automatically selected**, and repository
  deletion is review-only.
- **AI memory, conversation history, sign-in credentials and configuration are
  protected** and cannot be removed.
- **Model weights are review-only** and never selected.
- **Some system-level findings remain review-only.**
- Cleanup execution in this beta is limited to a **narrow safe subset**:
  clearly rebuildable developer build output, aged temporary files, and AI
  runtime/temporary/update-payload caches — and only when the evidence is
  strong and the scan of that location was complete. Everything else is
  read-only / review.
- **Full Disk Access may be needed** for broader visibility. Without it,
  Deep Scan runs and clearly reports which folders macOS hid.

CoreTend still has no telemetry, no analytics, no account, and makes no
network request other than the user-initiated update check.

## Not claimed

CoreTend does not "clean everything", is not "100% safe", and does not make
"all disk space recoverable". Deep Scan reports an *estimated* reclaimable
figure — on APFS the exact number is not knowable.

## Signing

This build is **Developer ID signed and notarized by Apple** (Team
`NSCUV5G738`); the app and DMG are stapled, so Gatekeeper opens them with no
override step.

Each release also ships a `SHA256SUMS` file signed with a Minisign key.
**The Minisign release-signing key has been rotated starting with
v1.2.0-beta.1:**

- Previous key ID: `A399E8FD75C1719E` — still the correct key to verify
  `v1.0.0` and earlier.
- New key ID: `F8473FB09E1DB730` — used from `v1.2.0-beta.1` onward.

The previous key was **not known to be compromised**; its private key could
no longer be unlocked, so it can no longer sign new releases. Apple
Developer ID signing and notarization are unchanged. If you previously
pinned `A399E8FD75C1719E`, download the new `minisign.pub` from this release
and confirm its key ID is `F8473FB09E1DB730` before trusting it.

```
minisign -Vm SHA256SUMS -p minisign.pub     # key ID F8473FB09E1DB730
shasum -a 256 -c SHA256SUMS
```
