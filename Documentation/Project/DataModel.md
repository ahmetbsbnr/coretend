# Local data model

CoreTend creates its local SQLite store under the reconstruction-specific Application Support namespace. `SQLiteStore` itself has no default path and never searches a home directory. Schema version is stored in `PRAGMA user_version`; version 1 contains the append-only `activity_events` table. Version 2 adds key/value preferences and a digest ledger for explicit legacy imports. Version 3 adds `performance_samples` with optional one-minute load average and optional available bytes. Version 4 adds `saved_files` for explicit favorites and opt-in Explore recents, retaining at most 100 non-favorites while preserving favorites. Paths and last measured logical/allocated byte counts are local; unknown measurements are SQL `NULL`. v1/v2/v3→v4 migrations run in one immediate transaction, preserve old rows and are repeatable; no historical paths are inferred during migration. Tests use synthetic v1/v2/v3 stores and unique temporary fixture roots.

SQLite preferences include sorted absolute exclusion paths and language selection. The recent-files opt-in is a local `UserDefaults` setting, off by default; only completed Explorer scans record up to 100 result paths. Favorites require explicit user action. A recent scan validates then writes its batch in one SQLite transaction; invalid input rejects the whole batch before writes. Turning recents off stops future inserts; Overview removes saved path records explicitly. The app receives exclusion folders through explicit folder pickers; all three scan surfaces pass saved exclusions into ScanCore. The recognized legacy input is exactly `coretend-preferences-v1.json`, schema version 1, allowlisted keys `version`, `excludedPaths`, `language`, maximum 1,000 paths, maximum 1 MB, regular file only, no symlink. Import copies these values, writes an audit event, keys retries by SHA-256 content digest, and never changes or deletes source. Other legacy formats remain unsupported pending evidence from a synthetic contract.

The last selected top-level destination is a separate raw identifier in local `UserDefaults` (`coretend.lastDestination`). An unknown value falls back to Overview. No last-scanned folder or file path is saved for navigation restoration.

Events distinguish proposals, approvals, refusals, cancellation, Trash success, and failure. They record action outcome, not claimed recovered space. Activity events have no automatic expiry and remain until the user explicitly clears them in Record; this clears event rows only. Preferences and exclusions remain until changed or the reconstruction-specific database is removed. This is a logical SQLite deletion, not a promise of forensic erasure of database or backups.

Performance samples are recorded only when the Performance view refreshes. A sample contains UUID, observation time, optional one-minute macOS load average and optional available volume bytes; unknown values stay SQL `NULL`, distinct from zero. Each insert prunes samples older than 30 days and retains at most 500 recent rows. The view displays up to 100, with separate points rather than interpolated measurements. The user can clear all saved samples from Performance after confirmation; activity events and preferences are unaffected. Opening or refreshing Performance then records a new sample.
