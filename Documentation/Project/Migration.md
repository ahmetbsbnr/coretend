# Migration boundary

The app never discovers legacy data by scanning a real user home. Import starts only after the user selects `coretend-preferences-v1.json` in the Settings file picker. Supported JSON v1 fields are `version`, `excludedPaths`, and optional `language`; unknown keys, path traversal, symbolic links, oversized files and unsupported language values are rejected. UI presents import preview and confirmation. Import copies only these values to schema v2, logs the operation, preserves source, and is idempotent by content digest. Other historical formats remain unsupported because no verified fixture contract is available. Schema v4 adds a local saved-file table: favorites are explicit, recent history is opt-in and off by default, unknown sizes remain null, and only 100 non-favorites are retained. v1/v2/v3 migrations preserve prior rows inside one immediate transaction; a failed migration rolls back. Synthetic v1/v2/v3 fixtures cover forward migration and repeat invocation.
